### [W3C 1998 年经典文章《Cool URIs Don&\#x27;t Change》再引热议](https://www.w3.org/Provider/Style/URI) ⭐️ 8.0/10

1998 年 W3C 发布的《Cool URIs Don&\#x27;t Change》一文至今仍是 URI 设计领域的经典指导。近期 Hacker News 上的讨论（255 分、62 条评论）揭示了该原则在现实中的持续挑战与部分缓解措施：用户报告微软 Windows 10 中的支持链接被重定向到通用页面，新闻网站频繁清理旧 URL，而 WordPress 等系统通过内置 301/302 重定向部分改善了链接持久性。然而，区域检测导致的重定向（如跳转到不同语言首页）仍会破坏链接共享，且许多机构（如 NSF）的旧链接依然返回 404 错误。文章自身的 URI 在 28 年间未发生变更，进一步印证了其理念的可行性。

hackernews · Klaster\_1 · 8月9日 14:32 · [社区讨论](https://news.ycombinator.com/item?id=49231809)

**「背景」** 1998 年，万维网发明人 Tim Berners-Lee 通过 W3C 发表了《Cool URIs Don&\#x27;t Change》一文，首次系统阐述了 URI 应保持稳定、不随意变动的核心原则，指出频繁更改 URI 会导致链接失效，破坏 Web 的互联性。该文成为 Web 架构的经典文献，其中列举的“好 URI”与“坏 URI”实例至今仍被反复引用，其持久性主张在随后的多次 Hacker News 讨论中持续引发共鸣。

**「影响」** 该讨论表明，尽管现代 CMS 系统提供了自动重定向机制，但机构层面的疏忽和设计不当仍会导致关键链接失效，影响用户体验并破坏信息可访问性。

**「社区讨论」** 社区普遍认同该原则的恒久价值，但指出实践中链接腐烂依然普遍，例如微软支持链接和 NSF 资源已失效，而基于地理位置的重定向进一步恶化了共享体验。部分评论认为，虽然现代重定向机制缓解了部分问题，但机构重组与忽视仍是主要障碍。

### [TileRT 软件能否让 NVIDIA GPU 实现超高交互性推理？](https://newsletter.semianalysis.com/p/ultra-high-interactivity-on-nvidia) ⭐️ 8.0/10

TileRT 软件通过将预填充（prefill）与解码（decode）拆分为独立引擎，试图在 NVIDIA GPU 上实现超高交互性的大语言模型推理。该架构包含一个高吞吐量预填充引擎和一个高交互性解码引擎，目标是在批大小为 1 的场景下，让 GPU 的交互延迟与 Cerebras、Groq LPU、SambaNova 等专用推理硬件相媲美。SemiAnalysis 的分析指出，这种解耦设计可能削弱专用 AI 加速器在低延迟交互上的优势，强化 NVIDIA 生态的竞争力。

rss · Semianalysis · 8月10日 04:51

**「背景」** 在大语言模型推理中，传统上预填充（处理输入提示）和解码（逐个生成令牌）在同一引擎中执行，往往难以兼顾高吞吐与低延迟交互。TileRT 提出一种分离式架构，将预填充与解码分配给不同引擎，使得 NVIDIA GPU 也能以 batch size 1 实现高交互性解码。近期，流行的 vLLM 推理框架通过 MultiConnector 与 TileRT 集成，两者共享预填充服务，但将低延迟解码请求路由至专门的 TileRT 引擎。

**「影响」** 若 TileRT 成功部署，NVIDIA GPU 在延迟敏感的 LLM 推理服务中或将不再需要依赖专用推理芯片，从而巩固其市场份额。

### [中国 AI 模型依赖 Nvidia 芯片，迁移华为成本高](https://www.scmp.com/tech/big-tech/article/3363491/chinas-top-ai-still-trained-nvidia-chips-what-delaying-switch-local-tech) ⭐️ 8.0/10

中国多家大模型开发者透露，目前最先进的 AI 模型仍在 Nvidia 芯片上训练，迁移到华为升腾芯片的主要障碍是软件生态不兼容。Nvidia 的 CUDA 代码无法直接在升腾上运行，需要大量重写和优化，一名研究人员估算迁移后时间和成本至少增加 50%。开源模型迁移约需两三名工程师额外工作一个月，而未公开源代码的模型则可能需要约十名工程师额外工作半年以上。部分团队已开始使用国产芯片，例如美团宣称其 LongCat-2.0 模型完全在 5 万张国产算力卡集群上训练和运行，但未披露供应商。

telegram · zaihuapd · 8月10日 09:44

### [Docker 发布 Sandboxes，为 AI 代理提供隔离执行环境](https://www.docker.com/products/docker-sandboxes/) ⭐️ 7.0/10

Docker 推出了名为 Docker Sandboxes 的新产品，为 AI 代理提供可丢弃的隔离执行环境。该产品基于 libkrun 的微虚拟机（microVM）而非容器实现强隔离，内置出站防火墙和密钥注入功能，以提升安全性与便利性。尽管工具本身并非开源且需要登录，但其针对 AI 代理沙箱化的实用设计已吸引开发者的广泛关注，社区中出现了 Locki 等开源替代方案。

hackernews · etoxin · 8月10日 06:02 · [社区讨论](https://news.ycombinator.com/item?id=49239751)

**「背景」** Docker Sandboxes 是 Docker 公司推出的一项服务，为 AI 编程代理（如 Claude Code、Gemini CLI 等）提供一次性、隔离的执行环境。与传统的容器隔离方式不同，它基于 libkrun 微虚拟机（microVM）实现更强的安全隔离，使代理能在无人值守的情况下安全运行代码和命令。

**「影响」** 对于需要隔离 AI 代理的开发人员，Docker Sandboxes 提供了开箱即用的微虚拟机隔离方案，但强制登录和闭源性质可能促使部分用户转向 Locki 或 Gondolin 等开源替代。

**「社区讨论」** 社区中，开发者认可其微虚拟机隔离和出站防火墙等实用功能，但对其闭源及登录要求存在分歧。部分用户已将其作为日常工具，另一些则构建了 Locki 等开源替代，同时也有质疑微虚拟机安全模型相较于传统虚拟机优势的声音。

**「影响」** 对于 AI 安全研究人员，该分析提供了从机制层面理解角色提示防御与攻击的视角，有助于开发更鲁棒的系统提示和防护措施。
