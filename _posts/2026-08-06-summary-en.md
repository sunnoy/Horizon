### [NVIDIA Vera Whitepaper Uncovers Spectre-like Value Prediction Feature](https://chipsandcheese.com/p/nvidias-vera-whitepaper-has-a-thread) ⭐️ 8.0/10

The discovery prompted immediate concern from security researchers, noting that such aggressive speculation may lead to a new wave of information leaks and require years of mitigations. The whitepaper specifically highlights performance gains from value prediction on &quot;agentic workloads,&quot; but the security implications are not addressed. hackernews · pella · Aug 5, 21:24 · [Discussion](https://news.ycombinator.com/item?id=49189234)

**「Background」** Value prediction is a speculative execution technique that allows a CPU to guess the result of an instruction before it completes, bypassing data dependencies to improve performance. This type of hardware feature was central to the Spectre family of vulnerabilities, which exploited speculative execution to leak sensitive data through side channels. NVIDIA’s Vera CPU whitepaper describes a value prediction feature in its Olympus core, raising concerns that it could reintroduce similar security risks.

**「Security risk from reintroduced speculative execution」** The inclusion of value prediction in NVIDIA&\#x27;s Vera processor could reintroduce Spectre-like transient execution vulnerabilities, potentially exposing confidential data in multi-tenant environments that rely on this hardware. Whether the vulnerability is exploitable depends on the final implementation and the effectiveness of any mitigations.

**「Community Discussion」** Community reaction highlighted deep concern that NVIDIA&\#x27;s adoption of value prediction reopens speculative execution vulnerabilities, with some experts predicting a lengthy cycle of exploits and mitigations. Others argued that benchmark comparisons from both NVIDIA and AMD are potentially misleading, questioning the marketing language around &quot;agentic workloads.&quot;

### [Bidirectional Diffusion Models Predict Rollout Errors Without Ground Truth](https://www.reddit.com/r/MachineLearning/comments/1vh2gn1/roundtrip_consistency_bidirectional_diffusion/) ⭐️ 8.0/10

A single bidirectional diffusion model can predict its own rollout errors without ground truth by measuring round-trip consistency: rolling forward then backward in time and using the discrepancy as a self-supervised error signal. The model is trained to step a dynamical system in either direction via a direction flag, and the round-trip inconsistency serves as a proxy for the unobservable rollout error. The approach requires no ensembles, held-out data, or governing equations, and is validated on tasks like CELEBV-HQ video generation and turbulent plasma simulations. Training both directions in one network outperforms two separate specialist models. The paper is accompanied by open-source code and a project page.

reddit · r/MachineLearning · /u/Clean-Hovercraft5825 · Aug 6, 12:10

**「Background」** Autoregressive diffusion models generate sequences by predicting one step at a time, but when deployed without ground truth, errors accumulate silently over long rollouts. The paper builds on conditional latent diffusion models that can be trained to step either forward or backward in time by using a direction flag, and it leverages the property that a round-trip prediction \(forward then backward\) should return to the start, turning the discrepancy into a self-supervised error signal.

**「Impact」** For developers of autoregressive generative models in domains such as video generation or digital twins, this technique offers a practical, test-time error estimation without ground truth, enabling detection of accumulated errors during long rollouts without additional data or models.

### [Apple iCloud Private Relay Leaks User IPs via Passkey](https://www.404media.co/apples-private-relay-is-exposing-users-real-ip-addresses/) ⭐️ 8.0/10

Security researchers Tommy Mysk and Talal Haj Bakry discovered that Apple&\#x27;s iCloud Private Relay fails to hide users&\#x27; real IP addresses when a website supports passkey authentication, due to a flaw in the WebKit engine that routes passkey requests through the system credential service, bypassing the proxy. The vulnerability affects all browsers on iOS, including the Tor-based OnionBrowser, and many websites may have inadvertently collected these IP addresses. Apple is investigating the issue after a separate leak of &\#x27;Hide My Email&\#x27; addresses was reported last month.

telegram · zaihuapd · Aug 6, 03:04

**「Background」** Apple&\#x27;s iCloud Private Relay is a privacy service that routes Safari traffic through two separate relays to obscure the user&\#x27;s IP address and location. Passkey is a passwordless authentication standard that uses public-key cryptography, where the system&\#x27;s credential service handles authentication requests outside the browser. On iOS, all browsers are required to use the WebKit engine, so any flaw in WebKit affects all browsers on the platform.

**「Impact」** The flaw allows any website that supports passkey authentication to obtain the real IP address of iOS users relying on iCloud Private Relay, exposing them to tracking and de-anonymization. Apple has not yet released a fix.
